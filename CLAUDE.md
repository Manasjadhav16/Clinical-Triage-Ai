## Architecture

This is a B2B HealthTech SaaS backend. A patient submits free-text symptoms; the system extracts clinical facts, scores triage severity, and returns a structured JSON note for a doctor's dashboard.

### Request Flow

```
POST /intake  →  run_intake_agent()  →  [future] run_analyst_agent()  →  [future] run_router_agent()  →  JSON response
```

- **`backend/api/main.py`** — FastAPI app and all REST endpoints. This is the only entry point from the outside world. `.env` is loaded here at startup so `GEMINI_API_KEY` (or other secrets) is available before any agent is initialised.
- **`backend/agents/`** — One file per agent. Each agent is a pure function (`run_*_agent`) that takes typed inputs and returns a Pydantic model. Agents do not share mutable state directly; they pass their output forward through the call chain.
- **`backend/schemas/models.py`** — Single source of truth for all Pydantic I/O models and the `AgentState` TypedDict. Every agent's input and output shape is defined here. Frontend rendering depends on these schemas being exact — do not loosen field types without a corresponding frontend change.

### Three-Agent Pipeline (target state)

| Agent | File | Input | Output schema |
|---|---|---|---|
| Intake (Agent 1) | `intake_agent.py` | `raw_symptoms: str` | `ExtractedFacts` |
| Clinical Analyst (Agent 2) | `analyst_agent.py` | `ExtractedFacts` | `TriageEvaluation` (TBD) |
| Dashboard Router (Agent 3) | `router_agent.py` | `TriageEvaluation` | `ClinicalNote` (TBD) |

### LLM & Structured Output

All agents use `langchain-google-genai` (`ChatGoogleGenerativeAI`, model `gemini-2.5-flash`). Structured output is enforced via `.with_structured_output(PydanticModel)` — never parse raw LLM strings manually. The `GEMINI_API_KEY` must be set in `.env` at the project root.

### Key Constraint

`AgentState` in `models.py` is the LangGraph shared state contract. When adding fields for a new agent phase, update `AgentState` first, then the agent, then the endpoint — never the reverse.
